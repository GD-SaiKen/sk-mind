# AI 原生企业数据平台 — 项目阶段性总汇报

日期：2026-07-10

---

## 一、项目是什么

> 汇聚企业分散在 ERP、MES、WMS、Excel 里的数据，通过轻量语义本体和 AI Agent 能力，**让业务人员可以直接用自然语言提问，得到可信、可追溯、有依据的答案**。

**目标客户**：中小型制造企业（MES/ERP 数据域）

**要解决的核心问题**：

| 问题 | 现状 | 目标 |
|---|---|---|
| 数据分散 | 数据在 ERP/MES/WMS/Excel/共享盘各自为政，查一个订单进度要翻 3 个系统 | 一个平台统一查询 |
| 质量不可见 | 不知道哪些数据有问题，基于错误数据做决策 | 数据质量自动检测、问题可追踪 |
| 决策靠人 | 老板想知道"哪些订单可能延期"，需要安排人查半天 | 直接问 Agent，给出答案和依据 |
| AI 不敢用 | 通用 AI 不了解企业数据，回答没有来源，不敢信 | Agent 回答带数据来源、指标口径、不确定性 |

## 二、怎么做的（总体架构）

```text
                    +------------------+
                    |   Agent 问答      |  阶段 3-4：让 AI 能回答业务问题
                    |   建议与协同      |           并推动人工确认闭环
                    +--------+---------+
                    +--------+---------+
                    |   语义图谱层      |  阶段 2：让平台理解数据代表什么业务对象、
                    |   对象/关系       |           对象之间有什么关系
                    +--------+---------+
                    +--------+---------+
                    |   可信数据底座    |  阶段 1 <-- 当前阶段
                    | Raw/Clean/Serving |  把企业数据接入平台，清洗整理，质量可见
                    +--------+---------+
 ERP | MES | WMS | Excel | 共享盘 | API        阶段 0：先搞清楚有哪些数据、接哪个系统
```

**思路**：不追求一步到位做大平台。先建底座（数据能进来、能查、能追踪来源），再搭语义（理解数据含义），最后上 Agent（自然语言问答）。**每层扎实了再往上走**。

## 五、当前卡点和风险

### 🔴 阻塞级：ERP 数据库连接信息未获取（ISS-001）

**这不是代码问题**——SqlServerConnector 代码已经写完，27 种类型映射都实现了。

**真正卡住的原因**：ERP SQL Server 的 IP、端口、数据库名、只读账号、网络白名单还没有从客户/运维侧拿到，导致无法在真实环境中验证连接器。

**影响**：阻塞 T06（执行链路）、T07（文件扫描）、T08（Excel 导入）、T09（Clean 层生成）共 4 个任务。

**需要的**：客户/运维提供 ERP SQL Server 的 **IP、端口、数据库名、只读账号、网络白名单**。拿到后 **1-2 人天**即可打通并演示"数据源登记 → SqlServer 数据导入"完整链路。

> ⚠️ 本质是外部依赖卡点。代码侧不受影响，可并行推进数据源管理、前端页面等不依赖 ERP 数据的任务。

### 🟡 风险：数据源管理前后端均未启动

T04（后端 API）和 T05（前端页面）是数据接入的用户入口，延迟启动会影响后续演示和客户验收。建议 W29 启动 T04。

- ❌ 独立图数据库 / RDF / OWL——轻量语义方案即可
- ❌ 湖仓 / Spark / Airflow——数据量远未到
- ❌ Kubernetes——Docker Compose 足够
- ❌ Agent 自动写回 ERP / MES 等核心系统——只做建议，人工确认
- ❌ 复杂审批流和工作流引擎
- ❌ 完整 BI 指标平台——只做当前够用的轻量指标管理
- ❌ 多租户 SaaS 商业化
