### ISS-001：ERP 数据库直连被拒绝，需调整数据接入策略 ^iss-001

| 字段 | 内容 |
|---|---|
| 发现周期 | W27 发现 → W29 升级 |
| 发现人 | 黄工（ERP 运维）正式回复 |
| 关联任务 | [[02-任务执行追踪表#T06|T06]], [[02-任务执行追踪表#T07|T07]], [[02-任务执行追踪表#T08|T08]], [[02-任务执行追踪表#T09|T09]] |
| 类型 | 🔴 卡点 |
| 严重程度 | ~~高（强制改变数据接入路径）~~ → 已降级为 P1 |
| 状态 | 🟢 已解决（d2a 链路跑通） |

**描述**
W29 收到 ERP 运维黄工正式回复，分两点：

**生产库直连**：❌ 明确拒绝。原因是违反信息安全保密协议，直连存在 5 大类风险（误删/篡改生产数据、拖垮性能、商业数据泄露、缺乏审计、合规违规）。不走审批——运维直接拒绝。

**副本库只读**：⏳ 等防火墙安装后，可走审批申请中转服务器只读账号。审批链路：直属上司欧阳慧娟经理评估 → 说明应用场景/是否连公网/使用人员保密协议。防火墙尚未安装，中转服务器未配置。

**关键转折**
黄工同时确认：**ERP 客户端支持批量导出 Excel**，可导出物料主数据、生产工单、出入库单据、库存报表、购销订单、成本明细等**全模块业务单据**。

**解决路径（已调整）**
W29 已通过 **d2a 中间机** 实现 ERP 数据接入：SQL Server `192.168.33.199:1433` → d2a 中间机 `192.168.33.185:8851` → d2a 平台 `192.168.33.186:8850` → sk-mind 同步引擎。三节点链路已跑通，Customer 1,060 行、Material 69,710 行、SalesOrder 8,317 行、SalesOrderLine 393 行已入平台。详见 [[data2agent修复报告]] 和 [[sk-mind与d2a关系定位说明|sk-mind 与 d2a 关系定位说明]]。

> **说明**：d2a 中间机部署在工厂内网，绕开了「生产库直连给外部系统」的合规问题——d2a 在工厂侧完成安全抽取和推送，sk-mind 不直接访问 ERP 数据库。

**当前策略（已降级 ISS-001 严重性）**
1. **主路径**：d2a 中间机 → d2a 平台 → sk-mind 同步引擎（✅ 已跑通）
2. **补充路径**：Excel 导入（T07/T08 降级为 P1，用于 d2a 模板未覆盖的 ERP 模块或非 ERP 系统数据）
3. **中长期**：副本库只读——等防火墙和中转服务器到位后，d2a 连接器可切换为副本库连接，作为更自动化的补充

**影响**
- d2a 已解决最核心的 ERP 数据接入问题，不再阻塞阶段 1
- Excel 连接器优先级从 P0 降为 P1（仍有价值，用于交叉校验和非 ERP 数据源）
- SqlServerConnector 代码保留用于 d2a 中转场景，非生产库直连

**建议优先级**：~~P0 立即调整~~ → P1 持续优化

**前置依赖**：无——d2a 链路已跑通，Excel 导出路径已确认可用

**预估工时**：d2a 链路已投入，持续维护；Excel 连接器后续开发 +3 人天

**解决记录**
- 解决周期：W29（7.13-7.17）d2a 三节点链路跑通
- 解决方案：通过 d2a 中间机作为工厂侧数据采集器，sk-mind 同步引擎从 d2a 平台拉取数据
- 7/17 修复：双节点 13 处修改，详见 [[data2agent修复报告]]

### ISS-FK-UUID：d2a FK=UUID vs ERP PK=业务编码不匹配，跨表 JOIN 失败 ^iss-fk-uuid

| 字段 | 内容 |
|---|---|
| 发现周期 | W29（7.17） |
| 发现人 | 1tang1315（data2agent 修复过程中发现） |
| 关联任务 | [[02-任务执行追踪表#T06|T06]], [[02-任务执行追踪表#T09|T09]] |
| 类型 | 🟡 Bug |
| 严重程度 | 中（影响跨对象关联查询） |
| 状态 | 🆕 新建 |

**描述**
d2a 中间件使用 UUID 作为业务对象的外键（如 SalesOrder.customer_ref 存的是 Customer 的 UUID），但 ERP 系统使用业务编码作为主键（如 CUSTOMER_CODE、DOC_NO）。导致跨表 JOIN 查询失败——Agent 无法通过"客户名称"找到对应"销售订单"。

**影响**
- d2a MCP 工具 query_objects 无法做跨对象关联查询
- sk-mind 同步引擎获取的数据中，customer_ref / material_ref 是 UUID 而非可读编码
- 数据浏览页面看到的外键是没有业务意义的 UUID 字符串

**建议方案**
1. **短期（应用层适配）**：sk-mind 同步引擎在 Stage 写入时，根据模板的 key_map 反查业务编码，将 UUID 替换为业务编码
2. **中期（d2a 侧修复）**：推动 d2a 模板在物化 obj_* 表时，外键列使用业务编码而非 UUID
3. **长期（语义层弥合）**：阶段 2 的语义关系模型在应用层显式定义对象间的关联方式，不依赖底层外键

**建议优先级**：P1 短期适配（影响数据可用性）

**前置依赖**：无

**预估工时**：应用层适配 1-2 人天
