## 当前问题

### ISS-001：执行链路为 stub，未接入真实连接器 ^iss-001

| 字段 | 内容 |
|---|---|
| 发现周期 | W27（6/30-7/6） |
| 发现人 | 代码审计 |
| 关联任务 | [[02-任务执行追踪表#T06|T06]], [[02-任务执行追踪表#T07|T07]], [[02-任务执行追踪表#T08|T08]], [[02-任务执行追踪表#T09|T09]] |
| 类型 | 🔴 卡点 |
| 严重程度 | 高（阻塞 Excel 导入和数据接入链路） |
| 状态 | 🆕 新建 |

**描述**
当前接入任务执行 API 通过 RQ 队列调用的 worker 任务是 `run_echo_sync`——一个仅打印任务名称的占位函数。真实的 SqlServerConnector、文件连接器、数据写入逻辑均未接入。

**根因**：不是代码没写好——SqlServerConnector 代码已完成——而是 **ERP 数据库的连接信息和访问权限还没有从客户/运维侧拿到**（IP、端口、数据库名、只读账号、网络白名单），导致无法在真实环境中验证和串联。

**影响**
- T06 虽然 API 完成度 85%，但核心执行链路不通（Worker 中跑的是 echo 占位）
- T07 的 SqlServerConnector 代码已完成，但缺少真实数据库连接信息无法验证
- T08、T09 完全被阻塞
- 数据浏览页只能读取已有测试数据，看不到新导入数据

> [!warning] 本质是外部依赖卡点，非技术阻塞。代码侧可并行推进 T04/T05/T10 等不依赖 ERP 数据的任务。

**建议方案**
1. **代码侧**：将 `run_echo_sync` 替换为真实的 `run_ingestion_task` 函数（1 人天）
2. **协调侧**：获取 ERP SQL Server 的 IP、端口、数据库名、只读账号、网络白名单（需客户/运维配合）
3. 拿到连接信息后，优先接入 SqlServerConnector 验证，再逐步接入文件连接器
4. 在 RQ Worker 中以同步方式运行连接器，FastAPI 层仅做任务调度

**建议优先级**：P1 本周处理

**前置依赖**：ERP 数据库连接信息（IP/端口/数据库名/只读账号/网络白名单），需客户或运维提供

**预估工时**：1-2 人天
