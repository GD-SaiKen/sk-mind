# sk-mind 与 d2a 关系定位说明

> **说明**：本文档澄清 sk-mind 与 data2agent (d2a) 两个项目的定位差异、职责边界和协作关系，避免团队内部和对外沟通中的概念混淆。基于 2026-07-20 三个项目的现状分析撰写。

---

## 一、两个项目是什么

| 维度 | data2agent (d2a) | sk-mind |
|---|---|---|
| 完整名称 | Data to Agent | AI 原生企业数据平台 |
| 当前版本 | v0.1.8（便携版，预编译分发） | v0.1.0（Docker Compose 部署） |
| 一句话定义 | 把工厂 ERP 数据安全地接给 AI Agent | 汇聚企业分散数据，通过语义本体和 Agent 让业务人员可问、可查、可追溯 |
| 面向角色 | 工厂 IT / 运维人员 | 业务人员 / 数据分析师 / 管理层 |
| 部署位置 | 工厂内网（靠近 ERP 数据库） | 中心服务器 / 云端 |
| 技术栈 | Python 3.14 嵌入式 + FastAPI + SQLite | Python + FastAPI + PostgreSQL + Vue 3 |
| 部署形态 | Windows 便携 exe（双击即用） | Docker Compose 多服务 |

## 二、核心定位差异

> **d2a 是工厂侧的「数据管道」，sk-mind 是中心侧的「数据平台」。两者是上下游协作关系，不是竞争或替代关系。**

```text
┌─────────────────────────────────────────────────────────────────┐
│                        ERP 生产数据库                             │
│                    (鼎捷 E10 / 易飞 / 金蝶)                        │
└────────────────────────┬────────────────────────────────────────┘
                         │ 只读抽取（水位增量、错峰窗口、限流）
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│                 d2a 中间机（工厂内网）                              │
│  • SQL Server 连接器（pyodbc）                                    │
│  • Raw 表落地（SQLite）                                          │
│  • 业务对象映射（YAML 模板 → obj_* 表）                           │
│  • 对账 / 隔离区 / 熔断器                                         │
│  • 推送到 d2a 平台（HTTP ingest）                                 │
└────────────────────────┬────────────────────────────────────────┘
                         │ HTTP 推送
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│                  d2a 平台（中心侧）                                │
│  • 接收中间机推送的数据批次                                        │
│  • MCP Server：query_objects / query_metrics / propose_action    │
│  • 运维控制台（仪表盘 / 同步状态 / 隔离区浏览）                      │
│  • 数据存储：SQLite（factory.sqlite）                             │
└────────────────────────┬────────────────────────────────────────┘
                         │ 同步引擎 v2（Fetcher → Raw → Stage）
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│                     sk-mind 平台（中心侧）                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐         │
│  │ 数据源管理 │  │ 接入任务  │  │ 数据分层  │  │ 数据质量  │         │
│  │ (CRUD)    │  │ (批次追踪)│  │ Raw/Clean │  │ (规则检查)│         │
│  └──────────┘  └──────────┘  │ /Serving  │  └──────────┘         │
│                               └──────────┘                       │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐         │
│  │ 语义本体  │  │ 关系图谱  │  │ Agent 服务│  │ 管理控制台│         │
│  │ (对象/属性)│  │ (业务边)  │  │ (问答/建议)│  │ (Vue 3)  │         │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘         │
│  数据存储：PostgreSQL + Redis                                    │
└─────────────────────────────────────────────────────────────────┘
```

## 三、职责边界：什么归谁做

### d2a 负责（不重复建设）

| 能力 | 说明 | 当前成熟度 |
|---|---|---|
| ERP 数据库直连 | 只读连接器、只读账号、ApplicationIntent=ReadOnly | ✅ 已跑通 |
| 增量同步水位 | keyset / 时间戳增量、错峰窗口、速率限制 | ✅ 已跑通 |
| 业务对象模板映射 | YAML 声明式绑定（ERP列 → 业务对象属性） | ✅ 5 个对象（计划 18 个） |
| 数据对账 | L1 分段 checksum + L2 深度行哈希 | ✅ 已实现 |
| 隔离区 + 熔断器 | 映射失败行隔离、超过阈值自动停止 | ✅ 已实现 |
| MCP 协议暴露 | query_objects / query_metrics / propose_action | ✅ 3 个工具 |
| 敏感字段脱敏 | 联系人、成本等字段默认 `***` | ✅ 已实现 |
| 审计日志 | 每次查询记录（d2a_audit_log） | ✅ 已实现 |

### sk-mind 负责（差异化建设）

| 能力 | 说明 | 当前进度 |
|---|---|---|
| 多源数据汇聚入湖 | 不只 ERP，还接 MES / SRM / Excel / API 等 | 🔄 同步引擎 v2 已跑通 |
| 数据分层治理 | Raw → Clean → Serving 三层，字段元数据管理 | 🔄 ~25% |
| 数据质量管理 | 规则定义 + 检查执行 + 问题追踪 | 🔄 模型已有 |
| **语义本体建模** | 业务对象/属性/关系定义、语义目录 | ⬜ 阶段 2（文档已有） |
| **业务关系图谱** | BusinessGraphEdge、跨对象推理 | ⬜ 阶段 2 |
| **Agent 编排服务** | 多轮对话、工具注册/编排、证据追溯 | ⬜ 阶段 3-4 |
| 前端管理控制台 | Vue 3 SPA，业务人员可用的完整 UI | 🔄 ~35% |
| 用户/权限/审计 | JWT + RBAC + 操作审计 | ✅ ~90% |
| 多租户部署 | Docker Compose，PostgreSQL 持久化 | ✅ ~90% |

### 协作接口

```text
d2a 平台（MCP Server）  ←──MCP 协议──→  sk-mind Agent 服务层
     │                                         │
     │  暴露 3 个工具：                          │  编排多个工具：
     │  • query_objects                        │  • d2a 数据工具
     │  • query_metrics                        │  • sk-mind 语义工具
     │  • propose_action                       │  • sk-mind 图谱工具
     │                                         │  • 外部 API 工具
```

sk-mind 的 Agent 服务层把 d2a 的 MCP Server 作为**一个数据工具源**接入，而不是替代它。d2a 继续做它擅长的「安全地从 ERP 取数并暴露」，sk-mind 在上层做「语义理解 + 多工具编排 + 用户交互」。

## 五、对接下来的影响

### 对 sk-mind 任务优先级的影响

> **Excel 连接器（T07/T08）不再是最高的 P0 优先级**，因为 d2a 已经提供了稳定的 ERP 数据接入通道。Excel 导入作为补充渠道（覆盖 d2a 模板未覆盖的 ERP 模块、或非 ERP 系统的 Excel 数据），优先级降为 P1。

当前实际的 P0 事项调整为：

1. **稳定 d2a → sk-mind 同步链路**：完善水位机制 + 异常处理 + 对账逻辑
2. **推进 d2a 侧模板补全**：18 个计划业务对象中还有 13 个未物化
3. **解决 FK-PK 不匹配**：让跨表关联可工作
4. **完成阶段 1 剩余模块**：让"可信数据底座"可闭环演示

### 对阶段 2-4 的影响

sk-mind 的阶段 2-4（语义本体 → Agent 查询 → Agent 建议）是 d2a 完全没有覆盖的领域，也是 sk-mind 真正的差异化价值所在。在阶段 1 数据底座稳定后，应**尽快启动阶段 2**，避免长时间停留在数据管道层面重复 d2a 已有能力。

## 六、对外沟通口径

| 场景 | 说法 |
|---|---|
| 向领导汇报 sk-mind 与 d2a 的关系 | "d2a 是数据管道，负责从 ERP 安全取数；sk-mind 是数据平台，负责汇聚多源数据、建立语义模型、提供 Agent 智能服务。两者是上下游协作，d2a 帮我们解决了最难的生产库连接问题。" |
| 向客户介绍 | "我们使用 d2a 作为工厂侧的数据采集器，安全地从您的 ERP 系统抽取数据；sk-mind 平台在中心侧统一管理所有数据，提供业务人员可以直接对话的 AI 助手。" |
| 团队内部分工 | "数据接入层的问题先看 d2a 侧能不能解决（模板补全、映射校准、FK问题），d2a 解决不了的才在 sk-mind 侧做适配。研发重心放在 d2a 做不了的语义层和 Agent 层。" |
