## 1. Vue 组件规范

### 1.1 组件命名

- 组件文件使用 **kebab-case**（与通用规范一致）
- 在模板中使用组件时，使用 **PascalCase** 或 **kebab-case**，同一项目内保持一致

```
✅ components/status-tag/index.vue
✅ components/page-header/index.vue
✅ <StatusTag :status="row.status" />
✅ <status-tag :status="row.status" />
```

### 1.2 单文件组件结构 — 固定顺序

**所有 `.vue` 文件必须严格按以下顺序组织**，不得将 `<script>` 置于 `<template>` 之前：

```vue
<template>
  <!-- 1. 模板内容 — 最先声明 -->
</template>

<script setup lang="ts">
// 2. 逻辑内容 — 其次
</script>

<style lang="scss" scoped>
// 3. 样式内容 — 最后
</style>
```

> **规则**：`<template>` → `<script>` → `<style>`（从上到下），这是硬性规定，不可调换。
>
> **使用 `script setup` 时**，如果确实需要额外的普通 `<script>` 块（如配置 `inheritAttrs`、`name` 等），该普通 `<script>` 块必须放在 `<script setup>` **之后**、`<style>` **之前**：
>
> ```vue
> <template>...</template>
>
> <script setup lang="ts">
> // 主要的组合式逻辑
> </script>
>
> <script lang="ts">
> // 额外选项（仅当必需时）
> export default { inheritAttrs: false }
> </script>
>
> <style lang="scss" scoped>...</style>
> ```

### 1.3 `<script>` 内部顺序

```vue
<script setup lang="ts">
// 1. 类型导入
import type { DataSource } from '@/types/data-source';

// 2. 第三方库导入
import { ElMessage, ElMessageBox } from 'element-plus';
import { computed, onMounted, ref, watch } from 'vue';

// 3. 项目内部导入
import { dataSourceService } from '@/api';
import { usePermission } from '@/composables/use-permission';
import { StatusTag } from './components/status-tag';

// 4. Props / Emits 定义
const props = withDefaults(defineProps<{
  sourceId?: number;
  readonly?: boolean;
}>(), {
  sourceId: undefined,
  readonly: false,
});

const emit = defineEmits<{
  submit: [data: Record<string, unknown>];
  cancel: [];
}>();

// 5. 响应式状态
const loading = ref(false);
const dataList = ref<DataSource[]>([]);
const searchKeyword = ref('');

// 6. 计算属性
const filteredList = computed(() =>
  dataList.value.filter(item =>
    item.name.includes(searchKeyword.value)
  )
);

// 7. 方法
async function loadData() {
  loading.value = true;
  try {
    const res = await dataSourceService.getList();
    dataList.value = res.data.items;
  } finally {
    loading.value = false;
  }
}

// 8. 生命周期
onMounted(() => {
  loadData();
});

// 9. 监听器
watch(() => props.sourceId, (newId) => {
  if (newId) loadData();
});
</script>
```

### 1.4 Props 与 Emits

- 使用 TypeScript 泛型声明，不用运行时声明

```vue
<!-- ✅ 推荐：类型声明 -->
<script setup lang="ts">
const props = withDefaults(defineProps<{
  title: string;
  count?: number;
  items: DataSource[];
}>(), {
  count: 0,
});

const emit = defineEmits<{
  change: [id: number];
  delete: [id: number, name: string];
}>();
</script>

<!-- ❌ 不推荐：运行时声明 -->
<script setup>
const props = defineProps({
  title: { type: String, required: true },
});
</script>
```

### 1.5 模板格式化规则

#### 1.5.1 标签属性换行规则

| 属性数量 | 格式 | 说明 |
|---|---|---|
| ≤ 2 个且单行不超过 80 字符 | 全部写在一行 | `<div class="home-page">` |
| ≥ 3 个属性 | 每个属性独占一行 | 标签名后换行，> 符号单独一行（非自闭合）或 `/>` 独立（自闭合） |

#### 1.5.2 属性少 — 单行

```vue
<!-- ✅ 属性 ≤ 2 个，单行 -->
<el-input v-model="keyword" placeholder="请输入数据源名称" />
<div class="user-name">管理员</div>
<span class="bread-sep">›</span>
<el-icon :size="16"><Bell /></el-icon>
```

#### 1.5.3 属性 ≥ 3 个 — 每个属性独占一行

每个属性缩进 2 空格，`>` 或 `/>` 放在属性之后的单独行：

```vue
<!-- ✅ 属性 ≥ 3 个，每个属性独占一行，/> 换行独立 -->
<el-table
  v-loading="loading"
  :data="filteredList"
  :default-sort="{ prop: 'updatedAt', order: 'descending' }"
  border
  stripe
  @selection-change="handleSelectionChange"
>
  <el-table-column type="selection" width="50" />
  <el-table-column prop="name" label="数据源名称" min-width="180" />
</el-table>
```

#### 1.5.4 包含文本内容的多属性标签

如果标签只有纯文本内容（无子元素），且属性较多，文本内容放在单独行：

```vue
<!-- ✅ 文本内容换行独立 -->
<el-tag
  effect="plain"
  style="background:#fdf6ec; color:#e6a23c; border-color:#faecd8"
>测试环境</el-tag>

<!-- ✅ 带 router-link 等包裹元素的标签 -->
<router-link
  v-for="item in navItems"
  :key="item.path"
  :to="item.path"
  class="nav-item"
  :class="{ active: route.path === item.path }"
>
  <el-icon :size="18">
    <component :is="item.icon" />
  </el-icon>
  <span v-if="sidebarOpen" class="nav-label">{{ item.label }}</span>
</router-link>
```

#### 1.5.5 通用规则

- 指令 (`v-if`, `v-for`, `v-model`) 放在属性列表最前面
- 自闭合标签使用 `<tag-name />` 形式
- 属性值中的对象/函数内容超过单行长度时，可折行内部缩进：

```vue
<!-- ✅ 属性值内部折行 -->
<el-tag
  effect="plain"
  style="background:#fdf6ec; color:#e6a23c; border-color:#faecd8"
>测试环境</el-tag>

<!-- ❌ 属性混在一起 — 禁止 -->
<el-table v-loading="loading" :data="filteredList" border stripe :default-sort=... ></el-table>
```

### 1.6 对象字面量格式 — 一属性一换行

无论在 `<script>` 还是 `<style>` 中，对象/映射的每个键值对必须独占一行，不得压缩成一行：

```typescript
// ✅ 一属性一换行
const rules: FormRules = {
  name: [
    { required: true, message: '请输入', trigger: 'blur' },
    { max: 128, message: '不能超过 128 个字符', trigger: 'blur' },
  ],
};

// ✅ Props 默认值
const props = withDefaults(defineProps<{
  sourceId?: number;
  readonly?: boolean;
}>(), {
  sourceId: undefined,
  readonly: false,
});

// ✅ 数组对象
const navItems = [
  { path: '/home', label: '首页' },
  { path: '/ingestion', label: '接入任务' },
];

// ❌ 禁止：多属性挤在一行
const rules = { name: [{ required: true, message: '请输入', trigger: 'blur' }] };
const navItems = [{ path: '/home', label: '首页' }, { path: '/ingestion', label: '接入任务' }];
```

> **例外**：单属性简写对象可以写在一行，如 `{ label: '首页' }`、`{ required: true }`。

## 2. TypeScript 规范

### 2.1 类型定义

- 优先使用 `interface`，需要联合类型或映射类型时使用 `type`
- 类型文件放在 `src/types/` 目录下，按模块拆分

```typescript
// src/types/data-source.ts
export interface DataSource {
  id: number;
  name: string;
  sourceType: 'database' | 'api' | 'file';
  status: 'active' | 'inactive' | 'error';
  owner: string;
  createdAt: string;
  updatedAt: string;
}

export type DataSourceFormData = Omit<DataSource, 'id' | 'createdAt' | 'updatedAt'>;
```

### 2.2 避免 `any`

- 禁止使用 `any`，确实无法确定类型时使用 `unknown`
- API 返回值必须声明类型

```typescript
// ❌
const data: any = await fetchData();

// ✅
const data: DataSource[] = await fetchData();

// ✅ 确实未知时
function parseResponse(raw: unknown): ParsedData { ... }
```

### 2.3 泛型命名

- 单泛型使用 `T`，多泛型使用有意义的前缀如 `TItem`、`TKey`

```typescript
export function usePagination<TItem>(
  fetchFn: (page: number) => Promise<{ items: TItem[]; total: number }>
) { ... }
```

## 3. Element Plus 使用规范

### 3.1 组件选择

- 表格：`el-table`（不用 `el-table-v2` 除非性能确实有问题）
- 表单：`el-form` + `el-form-item`
- 弹窗：`el-dialog`（简单确认用 `ElMessageBox`）
- 抽屉：`el-drawer`（详情或新增表单侧滑）
- 标签：`el-tag`（状态展示）
- 分页：`el-pagination`
- 通知：`ElMessage`（操作反馈）/ `ElNotification`（系统通知）

### 3.2 表格列宽

- `type="selection"` 列宽 `50`
- 状态列宽度 `80-100`
- 时间列宽度 `160-180`
- 操作列宽度按按钮数量 × 40 估算

### 3.3 表单校验

- 校验规则写在 `el-form` 的 `rules` prop 中，与后端校验保持一致

```vue

  :rules="rules"

  <el-form-item label="数据源名称" prop="name">
    <el-input v-model="formData.name" placeholder="请输入数据源名称" />
  </el-form-item>
</el-form>

<script setup lang="ts">
const rules: FormRules = {
  name: [
    { required: true, message: '请输入数据源名称', trigger: 'blur' },
```

## 4. SCSS 规范

> 本项目统一使用 SCSS，不使用纯 CSS。遵循以下约定。

### 4.1 属性书写格式

**每个 CSS 属性必须独占一行**，不得将多个属性写在同一行：

```scss
// ✅ 一属性一换行
.nav-item {
  display: flex;
  align-items: center;
  gap: 10px;
  padding: 8px 10px;
  border-radius: 8px;
  color: #374151;
  text-decoration: none;
  font-size: 14px;
  transition: background 0.15s;
}

// ❌ 禁止：多属性挤在一行
.nav-item { display: flex; align-items: center; gap: 10px; padding: 8px 10px; }
```

#### 属性书写顺序

按以下顺序排列（继承自通用规范）：

1. **定位**：`position` / `top` / `right` / `bottom` / `left` / `z-index` / `float` / `display`
2. **尺寸**：`width` / `height` / `min-width` / `max-width` / `min-height` / `max-height`
3. **盒模型**：`margin` / `padding`
4. **边框**：`border` / `border-radius` / `box-shadow`
5. **排版**：`font-size` / `font-weight` / `color` / `line-height` / `text-align` / `text-indent`
6. **背景**：`background-color` / `background-image` / `background-position` / `background-size`
7. **其他**：`cursor` / `opacity` / `transition` / `transform` / `overflow`

```scss
.data-table {
  // 1. 定位
  position: relative;
  display: flex;

  // 2. 尺寸
  width: 100%;
  max-width: 1200px;

  // 3. 盒模型
  margin: 0 auto;
  padding: 16px 0;

  // 4. 边框
  border: 1px solid #ebeef5;
  border-radius: 4px;

  // 5. 排版
  font-size: 14px;
  color: #303133;
  line-height: 1.5;

  // 6. 背景
  background-color: #fff;

  // 7. 其他
  cursor: pointer;
  transition: border-color 0.3s;
}
```

### 4.2 嵌套规则

- 子元素选择器嵌套在父级内，使用 SCSS 嵌套语法
- **父子关系**：直接子元素用 `>`，后代用空格
- **伪类/伪元素**：使用 `&` 符号嵌套在目标选择器内
- **状态修饰符**：使用 `&` 符号（如 `&:hover`、`&.is-active`、`&--disabled`）
- 嵌套深度**不超过 3 层**

```scss
// ✅ 正确的嵌套

  display: flex;
  padding: 16px;

  border-radius: 8px;

    .task-status {
      font-size: 12px;

      // 子元素内使用 & 表示父选择器
      &.is-running {
        color: #409eff;
      }

      &.is-success {
        color: #67c23a;
      }

      &.is-failed {
        color: #f56c6c;
      }
    }
  }

  > .task-body {
    display: flex;
    gap: 24px;

    .stat-item {
      display: flex;
      flex-direction: column;
      align-items: center;

      .stat-value {
        font-size: 24px;
        font-weight: 700;
        color: #303133;
      }

      .stat-label {
        font-size: 12px;
        color: #909399;
        margin-top: 4px;
      }
    }
  }

  // 伪类
  &:hover {
    border-color: #409eff;
    box-shadow: 0 2px 8px rgba(64, 158, 255, 0.15);
  }

  // 父级修饰符
  &--disabled {
    opacity: 0.5;
    pointer-events: none;
  }

```

### 4.3 禁止事项

- 禁止在 SCSS 中添加注释（代码即文档，选择器语义足够清晰）
- 禁止使用 `!important`（确有需要时通过提高选择器权重解决）
- 禁止使用 ID 选择器（`#xxx`）
- 禁止嵌套超过 3 层

### 4.4 变量与 Mixin

- 全局 SCSS 变量定义在 `src/styles/variables.scss`
- 全局 Mixin 定义在 `src/styles/mixins.scss`
- 通过 Vite 配置自动注入，不使用 `@import`


### 4.5 scoped 样式

- 组件样式默认使用 `<style lang="scss" scoped>`
- 需要穿透 Element Plus 内部样式时使用 `:deep()`

## 5. 状态管理 (Pinia)

### 5.1 Store 命名

- 文件名：`src/stores/<name>.ts`，kebab-case
- Store 名称：use + PascalCase + Store，如 `useDataSourceStore`

```typescript
// src/stores/data-source.ts
import { defineStore } from 'pinia';

export const useDataSourceStore = defineStore('dataSource', () => {
  const list = ref<DataSource[]>([]);
  const loading = ref(false);

  async function fetchList() {
    loading.value = true;
    try {
      const res = await dataSourceService.getList();
      list.value = res.data.items;
    } finally {
      loading.value = false;
    }
  }

  return { list, loading, fetchList };
});
```

## 6. API 请求层

### 6.1 请求封装

```typescript
// src/api/client.ts — axios 实例 + 拦截器
import axios from 'axios'
import { ElMessage } from 'element-plus'

const api = axios.create({
  baseURL: '/api',
  timeout: 30000,
  headers: { 'Content-Type': 'application/json' },
})

// 请求拦截：注入 token
api.interceptors.request.use((config) => {
  const token = localStorage.getItem('access_token')
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})

// 响应拦截：统一错误处理 + 401 自动跳转
api.interceptors.response.use(
  (response) => {
    const data = response.data
    if (data?.code !== undefined && data.code !== 0) {
      ElMessage.error(data.msg || data.message || '请求失败')
      return Promise.reject(new Error(data.msg || data.message))
    }
    return response
  },
  (error) => {
    if (error.response?.status === 401) {
      localStorage.removeItem('access_token')
      window.location.href = '/login'
      return Promise.reject(error)
    }
    const msg = error.response?.data?.detail ?? error.message ?? '网络错误'
    ElMessage.error(msg)
    return Promise.reject(error)
  },
)

export default api
```

### 6.2 类型定义

所有的 API 请求参数和响应数据类型集中定义在 `src/api/types.ts`，按模块分组：

```typescript
// src/api/types.ts
// ── Auth ──
export interface LoginParams {
  username: string
  password: string
}

// ── DataSource ──
export interface DataSource {
  id: number
  name: string
  sourceType: 'database' | 'api' | 'file'
  status: 'active' | 'inactive' | 'error'
  owner: string
  createdAt: string
  updatedAt: string
}

export type DataSourceFormData = Omit<DataSource, 'id' | 'createdAt' | 'updatedAt'>
```

### 6.3 服务类

每个业务模块对应一个**服务类**，封装所有相关接口方法。类名使用 PascalCase + `Service` 后缀，文件名使用 kebab-case：

```typescript
// src/api/services/data-source.ts
import api from '../client'
import type { DataSource, DataSourceFormData } from '../types'

export class DataSourceService {
  private api = api

  /** 获取数据源列表 */
  getList(params?: Record<string, unknown>) {
    return this.api.get('/data-sources', { params }).then(r => r.data.data)
  }

  /** 创建数据源 */
  create(data: DataSourceFormData) {
    return this.api.post('/data-sources', data).then(r => r.data.data)
  }

  /** 删除数据源 */
  delete(id: number) {
    return this.api.delete(`/data-sources/${id}`).then(r => r.data)
  }
}

export const dataSourceService = new DataSourceService()
```

#### 规范要点

- 服务类名：`PascalCase + Service`（如 `AuthService`、`IngestionService`）
- 文件名：kebab-case（如 `auth.ts`、`data-source.ts`、`ingestion.ts`）
- 每个服务类导出**单例实例**（`export const authService = new AuthService()`）
- 方法命名使用语义化名称（`getList`、`get`、`create`、`update`、`delete`）
- 实例名使用 camelCase（`authService`、`dataSourceService`）

#### 消费者使用

```typescript
// ✅ 在 .vue 文件中使用
import { authService, ingestionService, api } from '@/api'

// 服务类调用
await authService.login({ username, password })
const tasks = await ingestionService.getList({ pageSize: 20 })

// 直接使用 axios 实例（仅当没有对应服务类时）
const res = await api.get('/health')
```

## 8. 文件导入导出规范

### 8.1 模块统一导出（index 文件）

同一模块下的文件，使用 `index.ts` 统一导出：


### 8.2 导入路径规则

#### `.ts` / `.tsx` 文件

- 使用 `@/` 别名，省略 `index.ts`：

```typescript
// ✅ 省略 index.ts
import { usePagination } from '@/composables';
import type { DataSource } from '@/types';
import { dataSourceService } from '@/api';

// ✅ 等价于：
import { usePagination } from '@/composables/index';
import type { DataSource } from '@/types/index';
import { dataSourceService } from '@/api/index';
```

- 如果目标文件不是 `index.ts`，写完整路径（省略 `.ts` 后缀）：

```typescript
import { formatDate } from '@/utils/format';
import { TokenBucket } from '@/utils/rate-limiter';
```

#### `.vue` 文件

- `.vue` 文件**不支持**省略 `index.vue` 的路径简写，必须写完整路径：

```vue
<script setup lang="ts">
// ✅ .vue 文件：写完整路径
import StatusTag from '@/components/status-tag/index.vue';
import PageHeader from '@/components/page-header/index.vue';

// ❌ .vue 不能省略 index.vue（构建工具无法自动解析）
import StatusTag from '@/components/status-tag';
</script>
```

- 相对路径同理：

```vue
<script setup lang="ts">
import TaskForm from './components/task-form/index.vue';
import BatchLog from './components/batch-log/index.vue';
</script>
```

### 8.3 组件目录动态注册

当 `components/` 目录下文件较多（≥ 5 个），使用 `index.ts` 统一注册导出：

```typescript
// src/components/index.ts — 动态注册全局组件

import type { App } from 'vue';

// 需要全局注册的组件
const components: Record<string, Component> = import.meta.glob(
  './**/index.vue',
  { eager: true, import: 'default' }
);

export function registerGlobalComponents(app: App) {
  Object.entries(components).forEach(([path, component]) => {
    const name = path
      .split('/')
      .filter(p => p !== '.' && p !== 'index.vue')
      .pop();
    if (name && component) {
      app.component(name, component as Component);
    }
  });
}
```

```typescript
// main.ts
import { registerGlobalComponents } from '@/components';
registerGlobalComponents(app);
```

**但页面级组件（`views/`）不做动态注册**，页面组件使用路由懒加载即可。

### 8.4 导入路径速查

| 目标文件类型 | 是 index 文件时 | 非 index 文件时 |
|---|---|---|
| `.ts` / `.tsx` | `@/types`（省略 index） | `@/utils/format`（省略 .ts） |
| `.vue` | `@/components/status-tag/index.vue`（**不可省略**） | `@/views/data-source/detail.vue` |
| `.scss` | `@/styles`（如有 index.scss） | `@/styles/variables.scss` |
