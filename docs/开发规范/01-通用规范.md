## 1. 命名规则

### 1.1 文件命名

- 所有文件名统一使用 **kebab-case**（小写字母 + 连字符）
- 禁止使用 camelCase、snake_case、中文、空格或特殊符号

```
✅ 正确:
user-service.ts
ingestion-batch.vue
connector-config.py
api-pull-task.py

❌ 错误:
UserService.ts          （camelCase）
user_service.ts         （snake_case）
ingestionBatch.vue      （camelCase）
用户服务.ts              （中文）
```

- 当文件已处于明确的功能目录（如 `utils/`、`services/`）中时，文件名**不必重复目录名**

```
✅ src/utils/format.ts         （不重复 utils）
✅ app/modules/ingestion/models/ingestion_task.py
❌ src/utils/format-utils.ts   （冗余）
```

### 1.2 变量与函数命名

- 前端（TypeScript）和后端（Python）统一使用 **camelCase**（小驼峰），首字母小写

```typescript
// TypeScript 前端
const userList = ref<User[]>([]);
function formatDateTime(date: string): string { ... }
```

```python
# Python 后端
connector_config = load_connector_config(source_id)
def fetch_page_data(endpoint: str, page: int) -> dict: ...
```

- **Python 例外**：Python 生态惯用 snake_case，在纯后端代码中也允许使用 snake_case，但同一模块内必须一致

### 1.3 常量命名

- 统一使用 **UPPER_SNAKE_CASE**（全大写 + 下划线）

```typescript
// TypeScript
const MAX_RETRY_COUNT = 3;
const DEFAULT_PAGE_SIZE = 100;
const API_BASE_URL = '/api/v1';
```

```python
# Python
MAX_BATCH_SIZE = 50000
QPS_LIMIT = 10
REDIS_URL = "redis://localhost:6379/0"
```

### 1.4 类名与接口名

- 类名使用 **PascalCase**（大驼峰）
- 接口/类型名同样使用 PascalCase，前端 **不建议** 加 `I` 前缀

```typescript
// TypeScript
class TokenBucket { ... }
interface ConnectorConfig { ... }     // ✅
interface IConnectorConfig { ... }    // ❌ 不加 I 前缀
type SyncMode = 'full' | 'incremental';
```

```python
# Python
class SqlServerConnector(DatabaseConnector): ...
class IngestionBatch(Base): ...
```

### 1.5 Python 私有成员

- Python 类内部不对外暴露的方法/属性使用单下划线 `_` 前缀

```python
class SyncService:
    def execute_full_sync(self, ...):  # 公开方法
        ...

    def _build_raw_record(self, ...):  # 私有方法
        ...

    def _choose_batch_size(self, total):  # 私有方法
        ...
```

## 3. Import 顺序

### 3.1 前端 (TypeScript) Import 顺序

必须按以下顺序分组，组间空一行：

1. **内置模块**（Node.js / 浏览器 API）
2. **第三方库**
3. **项目共享模块**（`@/` 别名）
4. **相对路径导入**
5. **样式文件**

```typescript
// 1. 内置模块
import { computed, ref, watch } from 'vue';

// 2. 第三方库
import { ElMessage } from 'element-plus';
import axios from 'axios';

// 3. 项目共享模块
import { usePermission } from '@/composables/use-permission';
import type { DataSource } from '@/types/data-source';

// 4. 相对路径导入
import { StatusTag } from './components/status-tag';
import { formatDate } from '../utils/format';

// 5. 样式文件
import './detail.scss';
```

- 同组内，具名导入按**字母序**排列
- 单行导入优先，超过 120 字符或超过 6 个具名项时换多行

```typescript
// 单行（推荐）
import { computed, onMounted, ref } from 'vue';

// 多行（超过 6 项或 120 字符）
import {
  DataSource,
  IngestionBatch,
  IngestionTask,
  SourceObject,
} from '@/types/ingestion';
```

### 3.2 后端 (Python) Import 顺序

1. **标准库**
2. **第三方库**
3. **项目内部模块**
4. **同包内相对导入**

```python
# 1. 标准库
import hashlib
import json
from datetime import datetime, timedelta
from typing import Iterator, Optional

# 2. 第三方库
import httpx
from pydantic import BaseModel, SecretStr
from sqlalchemy import ForeignKey, String, func

# 3. 项目内部模块
from app.core.config import settings
from app.core.database import SessionLocal

# 4. 同包内相对导入
from .models.ingestion_batch import IngestionBatch
from .services.sync_service import SyncService
```

## 4. 注释规范

### 4.1 统一原则

- 注释使用**中文**
- 注释解释"为什么"，代码解释"是什么"
- 不写废话注释（如 `// 设置 name 为 '张三'`）

### 4.2 函数注释

```typescript
// TypeScript — JSDoc 风格
/**
 * 获取指定接口的分页数据。
 *
 * @param endpoint - 接口路径
 * @param params   - 查询参数
 * @param page     - 页码，从 1 开始
 * @returns 解析后的记录列表
 * @throws {HttpError} 当接口返回非 2xx 状态码时抛出
 */
async function fetchPage(
  endpoint: string,
  params: Record<string, unknown>,
  page: number = 1
): Promise<Record<string, unknown>[]> { ... }
```

```python
# Python — 函数/方法注释
def execute_full_sync(
    self,
    task_id: int,
    source_object_id: int,
    batch_id: str,
    rq_job,
) -> int:
    """
    执行全量同步任务。

    从源数据库分批次拉取全量数据，写入 PostgreSQL Raw 层物理表。

    Args:
        task_id: 接入任务 ID。
        source_object_id: 来源对象 ID。
        batch_id: 批次标识。
        rq_job: RQ 任务对象，用于更新进度。

    Returns:
        成功同步的行数。

    Raises:
        ConnectionError: 数据库连接失败时抛出。
    """
```

### 4.3 区块注释

- 使用 `# region` / `# endregion`（Python）或 `// region` / `// endregion`（TypeScript）对工具函数模块进行逻辑分组

```typescript
// region 日期格式化工具

/**
 * 将 ISO 日期字符串格式化为 `YYYY-MM-DD`。
 */
export function formatDate(iso: string): string { ... }

/**
 * 将 ISO 日期字符串格式化为 `YYYY-MM-DD HH:mm:ss`。
 */
export function formatDateTime(iso: string): string { ... }

// endregion
```

### 4.4 HTML 注释

- 仅在上层容器或区块上方使用简短注释
- 不要在标签内部加行内注释

```vue
<!-- 数据源基本信息卡片 -->
<div class="info-card">
  <el-descriptions :column="2" border>
    ...
  </el-descriptions>
</div>
```

## 5. Git 提交规范

### 5.1 Commit Message 格式

```
<type>(<scope>): <subject>

[body]
```

| type | 含义 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修复 Bug |
| `refactor` | 代码重构（不改变功能） |
| `docs` | 文档更新 |
| `style` | 代码格式（不影响逻辑） |
| `chore` | 构建/工具/依赖变更 |
| `test` | 测试相关 |

```text
✅ 正确:
feat(ingestion): 添加 SQL Server 全量同步任务
fix(api): 修复 API 连接器 429 重试后未恢复限流计数
docs(规范): 添加前后端开发规范文档
refactor(connector): 抽取 DatabaseConnector 抽象基类

❌ 错误:
update code
修改了一些东西
bug fix
```

### 5.2 分支命名

- 功能分支：`feat/<描述>`，如 `feat/sqlserver-connector`
- 修复分支：`fix/<描述>`，如 `fix/api-rate-limiter`
- 描述部分使用 kebab-case

## 6. API 约定

### 6.1 RESTful 风格

- 使用资源化路径、标准 HTTP 动词、明确的 HTTP 状态码语义

| 操作 | Method | 路径示例 |
|---|---|---|
| 列表查询 | `GET` | `/api/v1/data-sources` |
| 详情查询 | `GET` | `/api/v1/data-sources/{id}` |
| 创建 | `POST` | `/api/v1/data-sources` |
| 更新 | `PUT` | `/api/v1/data-sources/{id}` |
| 删除 | `DELETE` | `/api/v1/data-sources/{id}` |
| 执行动作 | `POST` | `/api/v1/ingestion-tasks/{id}/execute` |

### 6.2 响应格式

- 统一使用以下 JSON 结构：

```json
{
  "code": 0,
  "message": "success",
  "msg": "操作成功",
  "data": { ... }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | `int` | 业务状态码。`0` = 成功，非 `0` = 异常（前端统一拦截） |
| `message` | `string` | **英文技术状态**，如 `success`、`error`、`connection_failed`。供日志检索、监控告警、自动化判断使用 |
| `msg` | `string` | **中文用户提示**，如 `操作成功`、`数据源创建成功`。直接展示给用户，不用于逻辑判断 |
| `data` | `object\|null` | 业务数据，成功时返回，失败时为 `null` |

- 列表响应在 `data` 内包含分页信息：

```json
{
  "code": 0,
  "message": "success",
  "msg": "查询成功",
  "data": {
    "items": [ ... ],
    "total": 200,
    "page": 1,
    "pageSize": 20
  }
}
```

### 6.3 错误响应

```json
{
  "code": 40001,
  "message": "connection_failed",
  "msg": "数据源连接测试失败：无法连接到 192.168.1.100:1433",
  "detail": "Connection timeout after 30s"
}
```

| 字段 | 说明 |
|---|---|
| `code` | 非 0 错误码，前端统一拦截处理 |
| `message` | 英文错误标识（如 `connection_failed`, `permission_denied`, `sync_failed`），用于日志和告警 |
| `msg` | 中文错误描述，面向用户（如 `连接失败：无法连接到...`），**前端直接展示** |
| `detail` | 面向研发排查的技术细节，可包含堆栈摘要，**前端默认不展示** |

### 6.4 API 字段命名

**核心原则：前后端之间所有字段统一使用 camelCase。**

| 层级 | 要求 |
|---|---|
| 前端请求参数（Query/Body/Path） | **必须** camelCase |
| 前端读取的响应字段 | **必须** camelCase |
| 后端 API 接口的 JSON 字段 | **必须** camelCase |
| 数据库字段 | snake_case（PostgreSQL 惯例） |
| Python ORM 模型属性 | snake_case（与数据库一致） |

**前端禁止事项**：

- 禁止在页面、组件、Store 或 API 封装层中出现 `snake_case` 字段
- 禁止写双字段兼容逻辑（如 `obj.batch_id ?? obj.batchId`）
- 禁止在业务代码中手动做 `snake_case` ↔ `camelCase` 转换

**后端职责**：

- 后端负责在序列化时将 ORM 的 `snake_case` 字段转为 `camelCase` 输出
- FastAPI 响应模型使用 `alias` 或全局配置 `alias_generator` 完成转换
- 前端**不感知**数据库字段的 snake_case

**上游返回 snake_case 的处理**：

如果上游服务（如 MES API、SRM API）返回 `snake_case` 字段，**在共享请求层统一规范化**，不把转换逻辑散落到各个调用方：

```typescript
// ✅ src/utils/case.ts — 集中规范化的转换工具

import { camelCase, snakeCase } from 'lodash-es';

/** 将对象的 key 从 snake_case 递归转为 camelCase */
export function toCamelCase<T>(obj: unknown): T { ... }

/** 将对象的 key 从 camelCase 递归转为 snake_case（发往外部 API 时使用） */
export function toSnakeCase<T>(obj: unknown): T { ... }
```

```typescript
// ✅ src/utils/request.ts — 在请求层完成规范化

import { toCamelCase, toSnakeCase } from './case';

// 响应拦截：上游 snake_case → 前端 camelCase
request.interceptors.response.use((response) => {
  if (response.data) {
    response.data = toCamelCase(response.data);
  }
  return response;
});

// 请求拦截：前端 camelCase → 上游 snake_case（如需）
request.interceptors.request.use((config) => {
  if (config.data && config.serializeAsSnake) {
    config.data = toSnakeCase(config.data);
  }
  return config;
});
```

**业务代码的最终效果**：

```typescript
// ✅ 业务代码始终用 camelCase，完全透明
const batch = await fetchIngestionBatch(batchId);
console.log(batch.batchId);         // camelCase
console.log(batch.lastSyncTime);   // camelCase
console.log(batch.totalSuccess);   // camelCase

// ❌ 绝不允许
console.log(batch.batch_id);        // snake_case 泄漏
console.log(batch.last_sync_time);  // snake_case 泄漏
```
