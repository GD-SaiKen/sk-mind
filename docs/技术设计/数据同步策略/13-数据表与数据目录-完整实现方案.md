# 数据表与数据目录模块 — 完整实现方案

> 本方案基于 [[03-页面原型说明]] §8 数据表模块 + §9 数据目录模块，以及 [[原型梳理-页面与字段分析]] §四 数据表模块 + §五 数据目录模块的逐字段梳理，结合现有代码现状，给出前后端完整实现方案。

## 一、概念分析：两个模块到底代表什么

### 1.1 核心关系

数据表和数据目录是**同一份数据的两套视角**，不是两个独立的数据实体：

| 维度 | 数据表模块 (技术视角) | 数据目录模块 (业务视角) |
|---|---|---|
| 面向用户 | 数据负责人、技术人员 | 业务用户、Agent |
| 核心关注 | 表名、字段类型、空值率、主键、分层 | 业务说明、权限等级、质量状态、语义关联 |
| 列表展示 | 偏技术列：表名、层级、记录数、字段数 | 偏业务列：业务说明、权限等级、关联语义对象 |
| 详情重点 | 样例数据、字段列表、来源批次、语义映射 | 数据集说明、Agent使用限制、来源血缘 |
| 操作入口 | 编辑说明、配置权限、建立映射、执行质量检查 | 查看、搜索字段、了解业务含义 |

### 1.2 架构决策

> [!tip] 核心决策：数据目录不需要独立的数据表
> 数据目录是 `Dataset` 的**聚合投影视图**，不是独立实体。它通过 JOIN `datasets` + `dataset_fields` + `quality_issues` + `lineage` + 语义模型，组装出业务视角的展示数据。这避免了数据冗余和同步问题。

```
物理层（已有）:
  datasets 表          ← 数据集核心表
  dataset_fields 表    ← 字段元数据
  data_tables 表       ← 物理表登记
  quality_issues 表    ← 质量问题
  data_lineage 表      ← 血缘关系

逻辑层（本次实现）:
  datasets 模块 (技术视角 CRUD + 字段管理)
  catalog 模块 (业务视角聚合查询，无独立表)
```

### 1.3 两个模块的衔接点

| 衔接方向 | 说明 | 实现方式 |
|---|---|---|
| 数据表 → 数据目录 | 数据表字段维护(说明/敏感标记)后，数据目录自动同步 | 共享同一张 `datasets` 表，无同步问题 |
| 数据目录 → 数据表 | 用户在数据目录点击数据集，跳转到数据表详情查看技术详情 | 前端路由跳转，传递 `dataset_id` |
| 数据表 → 质量 | 数据表详情「质量结果」标签页 | JOIN `quality_issues` WHERE `dataset_id` |
| 数据目录 → 质量 | 数据目录列表展示质量状态 | 聚合查询最新质量检查结果 |
| 数据表 → 语义 | 数据表详情「语义映射」标签页 | JOIN 语义映射表（语义模型模块未实现，先用占位） |

### 3.3 数据目录模块（catalog）— 从零实现

#### 3.3.1 架构设计

> 数据目录模块**不创建独立的数据表**。它是一个聚合查询层，通过 JOIN 多张已有表组装出业务视角的数据。

```
catalog API 请求
  → catalog/service.py 组装查询
    → JOIN datasets + data_sources (来源名称)
    → LEFT JOIN quality_issues (质量状态聚合)
    → LEFT JOIN dataset_fields (字段目录)
    → LEFT JOIN data_lineage (来源血缘)
  → 返回业务视角的响应
```

async def catalog_get_dataset_detail(db, ds_id) -> dict:
    """数据集详情 — 业务视角。

    与 datasets.get_detail 的区别:
    - 不展示样例数据、空值率等技术信息
    - 增加: 数据集说明、Agent使用限制、来源血缘、关联语义对象
    - 权限和敏感字段信息更完整
    """
    ds = await db.get(Dataset, ds_id)
    if not ds:
        return None

    # 查来源
    source = await db.get(DataSource, ds.data_source_id) if ds.data_source_id else None

    # 查字段（业务视角，只取关键字段）
    fields = await _get_field_catalog(db, ds_id)

    # 查质量摘要
    quality = await _get_quality_summary(db, ds_id)

    # 查血缘
    lineage = await _get_lineage(db, ds_id)

    # 查敏感字段
    sensitive_fields = [f for f in fields if f.get("is_sensitive")]

    return {
        "id": str(ds.id),
        "name": ds.name,
        "display_name": ds.display_name,
        "description": ds.description,
        "source_name": source.name if source else None,
        "updated_at": ds.updated_at,
        "quality_status": ds.quality_status,
        "permission_level": ds.sensitivity_level,
        "is_agent_accessible": ds.is_agent_accessible,
        "agent_accessible_reason": ds.agent_accessible_reason,
        "semantic_object_code": ds.semantic_object_code,
        "record_count": ds.record_count,
        "field_count": ds.field_count,
        "fields": fields,
        "quality_summary": quality,
        "lineage": lineage,
        "sensitive_fields": sensitive_fields,
    }


async def catalog_get_stats(db) -> dict:
    """数据目录首页统计卡片。"""
    total = await db.scalar(select(func.count()).select_from(Dataset).where(Dataset.status == "active"))
    quality_ok = await db.scalar(select(func.count()).select_from(Dataset).where(
        Dataset.status == "active", Dataset.quality_status == "ok"
    ))
    quality_warning = await db.scalar(select(func.count()).select_from(Dataset).where(
        Dataset.status == "active", Dataset.quality_status == "warning"
    ))
    agent_accessible = await db.scalar(select(func.count()).select_from(Dataset).where(
        Dataset.status == "active", Dataset.is_agent_accessible == True
    ))
    return {
        "total": total,
        "quality_ok": quality_ok,
        "quality_warning": quality_warning,
        "agent_accessible": agent_accessible,
    }

## 七、关键设计决策记录

### 7.1 为什么数据目录不建独立表？

> 数据目录的本质是 `Dataset` 的业务投影，数据来源完全一致。如果建独立表，会产生数据同步问题——用户在数据表模块维护了字段说明，数据目录需要同步更新。共享 `datasets` 表避免了这个问题。

### 7.2 数据表模块和数据目录模块的 DAO 区别

| 维度 | datasets DAO | catalog DAO |
|---|---|---|
| 查询方式 | 简单 SELECT + WHERE | JOIN 多表聚合查询 |
| 返回数据 | ORM 对象 | dict（聚合视图） |
| 写操作 | 支持 CRUD | 只读，无写操作 |
| 筛选 | 按技术字段（data_layer, status） | 按业务字段（source_name, permission_level） |

### 7.3 DatasetField 的 is_sensitive 和 sensitivity_level

两个字段的关系：
- `sensitivity_level`（已有）：public / internal / sensitive / high_sensitive
- `is_sensitive`（新增）：布尔值，`sensitivity_level in ("sensitive", "high_sensitive")` 时为 True

`is_sensitive` 是冗余字段，但方便查询和前端展示。在 Service 层保持两者同步。

### 7.4 Agent 可用性的自动检查逻辑

```
检查条件（全部满足才可用）:
  ① 数据集状态为 active
  ② 质量状态不为 error
  ③ 所有敏感字段已标记（sensitivity_level != "internal" 的字段不能存在）
  ④ 字段说明覆盖率 > 50%（至少一半字段有 description）

不满足时返回具体原因列表，前端展示给用户。
```

### 7.5 样例数据查询的安全考虑

样例数据查询通过 `DataTable` 关联找到物理表名，执行 `SELECT * FROM {schema}.{table} LIMIT 100`。

> [!warning] SQL 注入风险
> 物理表名来自 `DataTable` 记录，不能直接拼接 SQL。必须使用参数化查询或 SQLAlchemy 的 `text()` + 白名单校验表名格式。

### 9.1 架构对比

### 9.2 d2a 数据目录的本质

d2a 的"数据目录"不是数据库查询视图，而是 **YAML 声明的业务对象模板**（`ObjectTemplate`）：

```yaml
# d2a/app/templates/objects/material.yaml
object: Material
display_name: 物料(品号)
description: 原材料、半成品与成品品号
domain: 产品
keys: [item_code]
properties:
  - { name: item_code, type: string, desc: 品号 }
  - { name: standard_cost, type: money, desc: 标准成本, sensitive: true }
bindings:
  - source: digiwin_e10
    tables: [ITEM]
    key_map: { item_code: ITEM.ITEM_CODE }
    field_map:
      item_code: ITEM.ITEM_CODE
      standard_cost: ITEM.STANDARD_COST
    watermark: ITEM.LAST_MODIFIED_DATE
```

Agent 调用 `query_objects()` 不带参数时，直接返回所有对象模板的目录（display_name / domain / properties / sensitive 标记）。这是 d2a 的"数据目录"——**模板即目录**。

### 9.3 五大设计模式借鉴建议

#### 模式1：业务对象概念层（借鉴）

d2a 的 `ObjectTemplate` 是物理表之上的业务抽象层。sk-mind 目前 Dataset 只登记物理表，缺少业务语义。

> **借鉴方案**：Dataset 增 `domain`（业务域）+ `object_type`（对象类型）；DatasetField 增 `semantic_mapping`（语义映射目标）。
> 不照搬 YAML 模板方式（sk-mind 是 API 驱动，物理表自动注册），而是在 Dataset 元数据上增加业务属性层。

#### 模式2：字段级源映射（借鉴）

d2a 的 `key_map` / `field_map` 提供完整的"源字段 → 目标属性"映射。sk-mind 的 YAML 接口声明里已有 `field_mappings`，但未写入 DatasetField。

> **借鉴方案**：DatasetField 增 `source_column` 字段，从 YAML 同步接口的 `field_mappings` 自动回填。
> 这样数据目录展示时，用户能看到"这个字段来自 MES API 的哪个原始字段"。

#### 模式3：隔离区 + 熔断器（部分已有，需增强）

d2a 的隔离区是行级（坏行进 quarantine 表），隔离率超阈值触发熔断。sk-mind B2.6 已实现隔离区端点。

> **借鉴方案**：① 数据目录详情增加"隔离率"展示；② Agent 可用性检查时，隔离率超阈值的数据集标记为不可用。

#### 模式4：数据集版本发布（暂缓）

d2a 有完整的 building → published → retired 版本状态机和原子发布/回滚。MES API 场景更新频率高（分钟级），版本发布的投入产出比低。

> **决策**：当前 draft/active/archived 三态足够。远期如需 Agent 读取稳定快照再考虑。

#### 模式5：Agent 治理档位（简化版借鉴）

d2a 的 看/说/做 三档治理体系完整但复杂。sk-mind 当前只需"看"档。

> **借鉴方案**：Dataset 增 `agent_tier` 字段（`query` / `advisory`），默认 `query`。当前只有只读查询场景，远期扩展再增加 `advisory`。
