# 02 — 数据库视图同步策略

版本：v0.1
日期：2026-07-08

## 文档说明

本文档定义**策略一：数据库视图同步**的通用技术方案。

适用场景：源系统开放只读数据库连接，表结构相对稳定，数据量大适合批量同步。本方案不绑定任何特定系统（ERP/MES/SRM），各系统的具体配置见 [05-数据源同步配置](./05-数据源同步配置.md)。

---

## 1. 策略概述

### 1.1 核心流程

```text
┌──────────────┐     ┌─────────────────┐     ┌──────────────────┐
│ 源数据库       │ →   │ SqlServer/MySQL  │ → │ PostgreSQL Raw 层 │
│ (SQL Server / │     │ Connector        │   │ raw_{前缀}_{表名} │
│  MySQL / PG)  │     │ (SQLAlchemy)     │   │ + 追踪字段        │
└──────────────┘     └─────────────────┘     └──────────────────┘
         │                    │                        │
         ▼                    ▼                        ▼
   只读连接              Schema 探测              批次 / hash / 来源
```

### 1.2 适用条件

| 条件 | 要求 |
|---|---|
| 连接方式 | 数据库只读账号，TCP/IP 可达 |
| 表结构 | 有明确的物理表或视图 |
| 数据量 | 单表千级到千万级均可，建议按数据量分级策略 |
| 增量字段 | 有时间戳字段（优先）或无时间戳（hash 兜底） |

### 1.3 不适用场景

- 源系统不开放数据库连接，仅提供 API → 用 [策略二：API 拉取同步](./03-API拉取同步策略.md)
- 源数据为文件（Excel/CSV）→ 走文件导入模块，不在本文档范围
- 需要实时 CDC 流同步 → 当前版本不纳入

## 2. Connector 设计

### 2.1 抽象接口

```python
class DatabaseConnector(ABC):
    """数据库连接器抽象基类"""

    @abstractmethod
    def connect(self) -> None: ...

    @abstractmethod
    def disconnect(self) -> None: ...

    @abstractmethod
    def test_connection(self) -> bool: ...

    @abstractmethod
    def fetch_schema(self, table_name: str) -> list[ColumnInfo]: ...

    @abstractmethod
    def fetch_table_list(self, schema: str = None) -> list[str]: ...

    @abstractmethod
    def fetch_data(
        self, table_name: str, columns: list[str] = None,
        where_clause: str = None, order_by: str = None,
        offset: int = 0, limit: int = 10000
    ) -> Iterator[dict]: ...

    @abstractmethod
    def count_rows(self, table_name: str, where_clause: str = None) -> int: ...
```

### 2.2 SQL Server 实现 (SqlServerConnector)

```python
class SqlServerConnector(DatabaseConnector):
    """SQL Server 连接器，基于 SQLAlchemy + pyodbc"""

    def __init__(self, config: SqlServerConfig):
        self.config = config
        self.engine = None

    def connect(self):
        conn_str = (
            f"mssql+pyodbc://{self.config.user}:{self.config.password}"
            f"@{self.config.host}/{self.config.database}"
            f"?driver={self.config.driver}&TrustServerCertificate=yes"
        )
        self.engine = create_engine(conn_str, isolation_level="READ UNCOMMITTED")

    def fetch_data(self, table_name, columns=None, where_clause=None,
                   order_by=None, offset=0, limit=10000):
        cols = ", ".join(columns) if columns else "*"
        sql = f"SELECT {cols} FROM {table_name}"
        if where_clause:
            sql += f" WHERE {where_clause}"
        if order_by:
            sql += f" ORDER BY {order_by}"
        sql += f" OFFSET {offset} ROWS FETCH NEXT {limit} ROWS ONLY"
        with self.engine.connect() as conn:
            yield from conn.exec_driver_sql(sql).mappings()
```

### 2.3 配置模型

```python
class SqlServerConfig(BaseModel):
    host: str                        # 如 "192.168.1.100\\SQLEXPRESS"
    port: int = 1433
    database: str                    # 如 "E10_3.0.0.2_CHS"
    user: str                        # 只读账号
    password: SecretStr              # 加密存储
    driver: str = "ODBC Driver 17 for SQL Server"
    schema: str = "dbo"              # 默认 schema
    connect_timeout: int = 30        # 连接超时(秒)
    query_timeout: int = 300         # 查询超时(秒)
```

## 3. 同步模式

### 3.1 全量同步 (FullSyncTask)

**执行主体**：RQ Worker 任务。

**流程**：

```text
1. 获取源表 Schema（字段名、类型、是否可为 NULL）
2. 在 PostgreSQL 创建/确认 Raw 物理表
   - 表名：raw_{系统}_{schema}_{源表名}
   - 字段：源表字段 + 追踪字段
3. 分批 SELECT 源数据（每批 10,000 行）
4. 计算每行 _source_row_hash
5. 分批 bulk_insert 到 PostgreSQL
6. 记录 batch_id、行数、耗时
```

**分批策略**：

| 源表数据量 | 批次大小 | 说明 |
|---|---|---|
| < 10 万行 | 10,000 行/批 | 默认 |
| 10 万 ~ 100 万行 | 20,000 行/批 | 适度增大批次 |
| > 100 万行 | 50,000 行/批 | 加大批次，减少事务数 |

**注意事项**：
- 使用 `READ UNCOMMITTED` 隔离级别（或 `WITH (NOLOCK)`），避免锁表影响业务
- 全量同步期间不阻塞其他任务，每批次独立事务
- 全量同步前可先 TRUNCATE Raw 表，或使用 `_batch_id` 区分不同批次的数据

### 3.2 增量同步 (IncrementalSyncTask)

**前置条件**：已完成至少一次全量同步。

**增量识别策略（按优先级）**：

| 优先级 | 策略 | 条件 | 方式 |
|---|---|---|---|
| 1 | **时间戳增量** | 源表有 `MODIFY_DATE` / `UPDATE_TIME` 等时间戳字段 | `WHERE modify_date > :last_sync_time` |
| 2 | **自增主键增量** | 源表有自增主键且只追加不修改 | `WHERE id > :last_max_id` |
| 3 | **Hash 对比兜底** | 无时间戳和自增主键 | 全量拉取 → 计算 hash → 与已有 hash 对比 → 只写入变更行 |

**时间戳增量流程**：

```text
1. 读取上次同步的 last_sync_time（从 ingestion_batch 记录）
2. SELECT * FROM {table} WHERE {timestamp_col} > :last_sync_time
3. 对变更行计算 hash、写入 PG
4. 更新 last_sync_time 为当前同步时间
```

**Hash 对比流程（兜底）**：

```text
1. 全量 SELECT 源表（可能很慢，仅用于无时间戳的小表）
2. 逐行计算 _source_row_hash
3. 从 PG 按 batch_id 查询已有 hash 集合
4. diff：
   - 新 hash（源有 PG 无）→ INSERT
   - 旧 hash 消失（PG 有源无）→ 标记 _is_deleted = true（不物理删除）
   - 相同 hash → 跳过
5. 记录新增/变更/删除数量
```

### 3.3 同步模式选择

| 场景 | 模式 |
|---|---|
| 首次接入 | 全量同步 |
| 日间增量更新（有时间戳） | 增量同步（时间戳） |
| 日间增量更新（无时间戳，小表） | 增量同步（hash 对比） |
| 源表结构发生 DDL 变更后 | 全量同步（重新拉取） |
| 数据修复/人工触发 | 全量同步（指定表） |

## 4. Schema 变化检测

### 4.1 检测流程

```text
每次同步前（可选）：
1. 获取源表当前 Schema（字段名、类型、nullable）
2. 获取 PG Raw 表当前 Schema
3. 对比：
   - 源表新增字段 → 记录差异，不自动 ALTER TABLE
   - 源表删除字段 → 记录差异
   - 字段类型变化 → 记录差异，标记为高风险
4. 产出 Schema 差异报告 → 存入 ingestion_batch.notes
5. 发送通知 → 人工决策是否调整 PG 表结构
```

### 4.2 差异报告格式

```json
{
  "table": "SALE_ORDER",
  "detected_at": "2026-07-08T02:00:00Z",
  "changes": [
    {
      "type": "column_added",
      "column": "NEW_FIELD",
      "data_type": "nvarchar(100)"
    },
    {
      "type": "type_changed",
      "column": "AMOUNT",
      "old_type": "decimal(18,2)",
      "new_type": "decimal(20,4)",
      "risk": "high"
    }
  ]
}
```

**原则**：Schema 变更不自动执行。自动 ALTER TABLE 可能导致下游 Clean/Serving 视图断裂。差异应进入人工确认流程。

| SQL Server 类型 | PostgreSQL 类型 | 备注 |
|---|---|---|
| `int` / `integer` | `INTEGER` | |
| `bigint` | `BIGINT` | |
| `smallint` | `SMALLINT` | |
| `tinyint` | `SMALLINT` | |
| `bit` | `BOOLEAN` | |
| `decimal(p,s)` / `numeric(p,s)` | `NUMERIC(p,s)` | |
| `float` | `DOUBLE PRECISION` | |
| `real` | `REAL` | |
| `money` / `smallmoney` | `NUMERIC(19,4)` | |
| `datetime` | `TIMESTAMP` | |
| `datetime2` | `TIMESTAMP` | 精度更高 |
| `smalldatetime` | `TIMESTAMP` | |
| `date` | `DATE` | |
| `time` | `TIME` | |

| `char(n)` | `CHAR(n)` | |
| `varchar(n)` | `VARCHAR(n)` | |

| `text` / `ntext` | `TEXT` | |

| `xml` | `XML` | |

### 5.2 MySQL → PostgreSQL 类型映射（预留）

若后续接入 MySQL 数据源，类型映射与此类似。核心差异：`TINYINT(1)` → `BOOLEAN`，`DATETIME` → `TIMESTAMP`，`TEXT`/`MEDIUMTEXT`/`LONGTEXT` → `TEXT`。

## 6. Raw 层物理表规范

### 6.1 命名规范

```
raw_{系统标识}_{schema}_{源表名}
```

示例：
- `raw_erp_dbo_SALE_ORDER` — ERP 的 SALE_ORDER 表
- `raw_erp_dbo_INVENTORY` — ERP 的 INVENTORY 表

### 6.2 Raw 表 DDL 生成规则

```sql
-- 追踪字段模板（追加到每个 Raw 表末尾）
_raw_id          BIGSERIAL PRIMARY KEY,
_batch_id        VARCHAR(64)  NOT NULL,
_source_system   VARCHAR(64)  NOT NULL DEFAULT 'ERP_E10',
_source_object   VARCHAR(256) NOT NULL,          -- 源表名
_source_row_hash VARCHAR(64)  NOT NULL,          -- SHA-256
_ingested_at     TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
_is_deleted      BOOLEAN      NOT NULL DEFAULT FALSE  -- 增量 hash 对比时标记
```

### 6.3 索引规范

| 索引 | 字段 | 用途 |
|---|---|---|
| `idx_{表}_batch` | `_batch_id` | 按批次查询数据 |
| `idx_{表}_hash` | `_source_row_hash` | 增量 hash 对比 |
| `idx_{表}_ingested` | `_ingested_at` | 按时间查询 |
| 主键索引 | 源表主键（如有） | 业务查询 |

## 7. 数据量分级与策略选择

| 数据量级 | 全量同步策略 | 增量同步策略 | 调度建议 |
|---|---|---|---|
| **小表** (< 1 万行) | 一次 SELECT 全量拉取 | 时间戳增量（高效）或 hash 对比 | 每小时 |
| **中表** (1 万 ~ 100 万行) | 分批 10,000-20,000 行/批 | 时间戳增量 | 每日 T+1 |
| **大表** (> 100 万行) | 分批 50,000 行/批，可能跨多批次 | 时间戳增量 + 分区游标 | 每日 T+1，分时段 |

首次全量同步时，应先同步小表 → 中表 → 大表，确保依赖关系正确（如先同步主数据表，再同步交易表）。

## 8. 作业编排

### 8.1 单表同步流程

```python
def run_full_sync(connector, table_name, pg_session, batch_id):
    """单表全量同步"""
    # 1. Schema 检测
    src_columns = connector.fetch_schema(table_name)
    pg_columns = get_pg_raw_columns(pg_session, table_name)

    # 2. 如果需要，创建/更新 Raw 表
    if not pg_columns:
        create_raw_table(pg_session, table_name, src_columns)

    # 3. 分批拉取 + 写入
    total_rows = connector.count_rows(table_name)
    offset = 0
    while offset < total_rows:
        rows = connector.fetch_data(table_name, offset=offset, limit=10000)
        records = []
        for row in rows:
            record = dict(row)
            record['_batch_id'] = batch_id
            record['_source_row_hash'] = compute_hash(record)
            record['_source_object'] = table_name
            records.append(record)
        pg_session.bulk_insert_mappings(RawModel, records)
        pg_session.commit()
        offset += 10000

    return total_rows
```

### 8.2 多表编排

```text
Phase 1: 主数据表（Customer, Supplier, Material, Employee...）
Phase 2: 配置表（Warehouse, BOM, Unit...）
Phase 3: 交易表（SalesOrder, PurchaseOrder, ProductionOrder...）
Phase 4: 流水表（InventoryTransaction, JournalEntry...）
```

每个 Phase 内的表可并行同步（不同 RQ Job），Phase 之间串行保证依赖。
