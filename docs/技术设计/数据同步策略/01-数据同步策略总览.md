## 1. 两种策略的定位

| 策略 | 定位 | 适用条件 |
|---|---|---|
| **数据库视图同步** | 直连业务数据库，SELECT 方式拉取数据 | 源系统开放只读数据库连接；表结构相对稳定；数据量大、适合批量同步 |
| **API 拉取同步** | 通过 HTTP API 接口拉取数据 | 源系统提供 REST API；接口有分页和限流；响应结构可能随版本变化 |

两种策略**互不排斥**。同一个系统（如 ERP）如果有 API 也有数据库直连，优先选数据库视图同步（效率高、可控性强）。如果同一系统部分数据只有 API 提供（如 MES 自定义字段），则同时使用两种策略，但分属不同接入任务。

核心原则：**策略是手段，数据进平台是目的**。不要为了统一策略而强制所有源系统走同一条路。

## 2. 数据流全链路

无论哪种策略，数据进入平台后都走统一的分层链路：

```text
┌──────────┐    ┌───────────────┐    ┌──────────┐    ┌───────────┐    ┌──────────────┐
│ 数据源     │ →  │ Connector 层   │ →  │ Raw 层    │ →  │ Clean 层   │ →  │ Serving 层    │
│           │    │               │    │          │    │           │    │              │
│ ERP DB    │    │ SqlServer     │    │ raw_erp_* │    │ 类型转换   │    │ serving_     │
│ MES API   │    │ Connector     │    │ 物理表     │    │ 标准化     │    │ 视图/物化视图 │
│ SRM API   │    │ ApiConnector  │    │           │    │ 质量标记   │    │              │
│           │    │               │    │ raw_record │    │ 去重       │    │              │
│           │    │               │    │ JSONB 表   │    │           │    │              │
└──────────┘    └───────────────┘    └──────────┘    └───────────┘    └──────────────┘
                         │                  │               │                │
                         ▼                  ▼               ▼                ▼
                    连接管理            批次追踪          质量状态          数据目录
                    状态检测            来源记录          问题清单          Agent 入口
```

### 2.1 各层职责

| 层级 | 数据库视图同步 | API 拉取同步 | 共性 |
|---|---|---|---|
| **Connector** | `SqlServerConnector`：建立只读连接、获取 Schema | `ApiConnector`：管理 token/鉴权、限流、分页 | 连接测试、状态检测 |
| **Raw** | 按源表生成 PostgreSQL 物理表，保留原始字段 | 存入 `raw_record` JSONB 通用表，保留原始响应 | 均追加 `_batch_id` / `_ingested_at` / `_source` |
| **Clean** | 类型转换、格式标准化、质量校验、去重 | 从 JSONB 展开字段、类型推断、质量校验 | 统一的质量标记规范 |
| **Serving** | 创建业务视图连接多表 | 从 JSONB 创建结构化视图 | 统一命名规范 `serving_{对象}` |

### 2.2 追踪字段规范

所有 Raw 层数据（无论物理表还是 JSONB 表）至少追加以下追踪字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `_raw_id` | UUID / BIGSERIAL | 平台内唯一标识 |
| `_batch_id` | VARCHAR(64) | 接入批次 ID，关联 `ingestion_batch` 表 |
| `_source_system` | VARCHAR(64) | 来源系统标识，如 `ERP_E10`、`MES_LIGHT`、`SRM` |
| `_source_object` | VARCHAR(256) | 来源对象，如表名、接口路径 |
| `_source_row_hash` | VARCHAR(64) | 原始行数据 hash（SHA-256），用于增量对比 |
| `_ingested_at` | TIMESTAMPTZ | 数据入库时间 |

数据库视图同步的物理表额外追加：

| 字段 | 说明 |
|---|---|
| `_source_file_path` | 仅文件导入场景使用，数据库同步可为 NULL |
| `_source_row_number` | 仅文件导入场景使用 |

API 拉取同步的 JSONB 表额外追加：

| 字段 | 说明 |
|---|---|
| `_api_url` | 接口完整 URL |
| `_api_request_params` | 请求参数 JSON（脱敏后） |
| `_api_response_at` | 接口响应时间 |

## 3. 共性设计原则

### 3.1 批次与状态

每次同步执行生成一个独立批次 (`ingestion_batch`)，状态流转：

```text
pending → running → success / partial_success / failed
                         ↓
                      可重试 → 新批次
```

- `partial_success`：部分数据成功入库，部分失败（如个别行格式错误），不阻塞已成功数据
- `failed`：连接失败、认证失败、Schema 结构不可识别等全局性错误

### 3.2 错误处理

| 错误类型 | 处理方式 | 影响范围 |
|---|---|---|
| 连接失败 | 重试 3 次，指数退避，仍失败则标记 `failed` | 整个批次 |
| 认证/权限失败 | 不重试，立即 `failed` 并告警 | 整个批次 |
| 单行数据格式错误 | 跳过该行，记录错误明细，继续处理 | 该行 |
| Schema 结构变化 | 记录差异报告，`partial_success`，不自动变更 | 新增/变更字段 |
| API 限流 (429) | 等待 Retry-After 头指示时间后重试 | 该页 |
| API 超时 | 重试 3 次，仍失败则记录并跳过该页 | 该页 |

### 3.3 重试策略

| 场景 | 策略 |
|---|---|
| 连接/网络类错误 | 指数退避：1s → 2s → 4s，最多 3 次 |
| API 限流 | 读取 `Retry-After` 响应头，等待后重试 |
| 用户手动重试 | 生成新批次（新 `batch_id`），不覆盖旧批次记录 |

### 3.4 权限与安全

- 数据库连接：**只读账号**，最小权限（仅 SELECT 授权表范围）
- API 密钥：加密存储，管理台仅展示最后 4 位
- 连接配置：凭据不入日志、不入批次记录
- 数据出网：所有同步在后端执行，明细数据不离开客户内网

### 3.5 调度策略

| 触发方式 | 适用场景 |
|---|---|
| **手动执行** | 初始全量同步、问题修复后重试 |
| **定时执行** | T+1 日间低峰增量同步（如每日凌晨 2:00） |
| **按需执行** | Agent 触发受控查询或报告生成（轻量即时查询，不走全量同步链路） |

定时策略通过 APScheduler 或系统 cron 触发，不引入 Airflow 等复杂调度平台。详细的增量对比机制、时间范围策略、定时编排见 [[07-增量更新与定时同步策略]]。

## 4. 与现有技术方案的对齐

| 技术方案要求 | 本策略覆盖 |
|---|---|
| PostgreSQL 优先（§8.1） | Raw/Clean/Serving 均在 PostgreSQL 中实现 |
| 异步任务 RQ + Redis（§7.2） | 同步任务由 RQ Worker 执行 |
| 批次与错误追踪（§7.3） | 统一的 `ingestion_batch` 和 `import_error` 模型 |
| Raw 层保留来源（§8.3） | 追踪字段 + 来源记录 |
| Clean 层质量标记（§8.4） | 统一的清洗规则和质量标记 |
| Serving 层受控入口（§8.5） | 视图/物化视图 + 权限控制 |
| 模块化单体（§6.1） | Connector + Task 均在 `app/modules/ingestion/` 下 |

## 5. 策略选择决策树

```text
源系统是否开放数据库只读连接？
├── 是 → 数据库视图同步
│   └── 特殊情况：少量字段仅 API 提供 → 同时建一个 API 拉取任务
└── 否 → API 拉取同步
    └── 是否有分页？
        ├── 是 → 标准分页拉取
        └── 否 → 单次拉取，依赖接口返回全量
```

对于本项目的三大数据源：
- **ERP (E10)**：有 SQL Server 数据库 → **数据库视图同步**
- **MES (LightMES)**：仅提供 REST API → **API 拉取同步**
- **SRM**：仅提供 REST API → **API 拉取同步**
