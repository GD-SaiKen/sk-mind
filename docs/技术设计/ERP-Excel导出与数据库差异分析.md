# ERP Excel 导出 vs 原始数据库 差异分析

> 结论：ERP Excel 导出均为**报表级加工数据**，非任何单张原始表的直接 dump。但数据已有字段翻译和 JOIN 展开，导入后可直接使用。

---

## 样本：生产进度表.csv

- 对应模块：[[MO (制造工单)]]
- 涉及表：`MO` + `ITEM` + `ITEM_FEATURE` + `MO_ROUTING` + `MO_ROUTING_WORK_CENTER` + `MO_RECEIPT_REQUISTION` + `ORDER` + `CUSTOMER`
- 数据量：~24 万行
- 加工深度：**重度加工**（报表级）

### 直接来自 MO 表（11 个字段）

工单单号、状态码、紧急、预计产量、需求数量、已生产量、报废数量、破坏数量、预计开工日期、预计完工日期、备注

### JOIN 展开（7 个字段，GUID→名称）

产品品号/品名/规格、特征码/规格、单位名称、工厂——均为 `MO.ITEM_ID` 等 GUID 外键→关联表名称字段

### 跨表聚合/计算（4 个字段）

入库申请数量（SUM）、最早/最晚开工完工日期（MIN/MAX 跨工艺行）、工作中心（三级 JOIN）

### 跨模块关联（6 个字段，4~5 级 JOIN）

需求单号、客户、客户品号、品号属性项、订单日期——走 MO→ORDER→CUSTOMER 链路

---

## 样本：库存明细表.csv

- 对应模块：[[ITEM (物料商品)]]
- 涉及表：`ITEM_WAREHOUSE_BIN` + `ITEM` + `ITEM_FEATURE` + `WAREHOUSE` + `ITEM_GROUP` + `PLANT`
- 数据量：~1.6 万行
- 加工深度：**中度加工**（查询视图级）

### 直接来自 ITEM_WAREHOUSE_BIN 表（2 个字段）

数量、第二数量

### JOIN 展开（12 个字段，GUID→名称）

品号、品名、规格、单位、特征码/规格、仓库编号/名称、工厂编号/名称、群组编号/名称、计划员码、第二单位

---

## 对平台的影响

| 影响 | 说明 |
|---|---|
| **有利** | Excel 数据是业务就绪的——GUID 已翻译、字段名已是中文、JOIN 已展开。导入后无需再做数据清洗和关联 |
| **不利** | 无法还原单表原始结构。如果需要做跨表去重、字段级血缘追踪，需原始表数据（等副本库只读方案） |
| **数据量** | 可控。最大表 24 万行，Excel 可直接导入，不需要分片 |
