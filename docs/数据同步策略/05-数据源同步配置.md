# 05 — 数据源同步配置

版本：v0.1
日期：2026-07-08

## 文档说明

本文档给出 **ERP / MES / SRM 三大数据源的具体同步配置实例**，包括策略选型、P0 级表/接口清单、同步频率、特殊限制和风险。

本文档是 [02-数据库视图同步策略](./02-数据库视图同步策略.md) 和 [03-API拉取同步策略](./03-API拉取同步策略.md) 在三个系统上的**落地配置**。

## 1. ERP (E10) 同步配置

### 1.1 基本信息

| 项目 | 值 |
|---|---|
| 系统名称 | E10 ERP |
| 厂商 | 鼎捷软件 |
| 版本 | E10 3.0.0.2 CHS |
| 数据库类型 | Microsoft SQL Server |
| 数据库名 | E10_3.0.0.2_CHS |
| 服务器 | .\SQLEXPRESS（或内网 IP） |
| 数据规模 | 1,989 表 / 224 模块 / 90,599 字段 |
| 数据源登记卡 | `docs/数据梳理/ERP/梳理后/ERP数据源登记卡.md` |

### 1.2 策略选型

| 决策项 | 选择 | 理由 |
|---|---|---|
| **同步策略** | 数据库视图同步 | 有 SQL Server 只读连接 |
| **全量同步** | 初始接入 + 结构变更后 | SELECT 分批拉取 |
| **增量同步** | 每日 T+1 凌晨 | 依赖时间戳字段 `MODIFY_DATE` |
| **Raw 存储** | PostgreSQL 物理表 | 表结构稳定，适合物理表 |

### 1.3 接入范围与优先级

ERP 共 8 个核心业务域，本次聚焦 P0 级表（共 103 张）。

| 业务域 | P0 表数 | 总表数 | 优先级 | 首轮接入计划 |
|---|---|---|---|---|
| 财务核算 | 22 | 273 | **P0** | 第一期 |
| 销售分销 | 18 | 252 | **P0** | 第一期 |
| 库存管理 | 15 | 111 | **P0** | 第一期 |
| 生产制造 | 16 | 220 | **P0** | 第一期 |
| 采购供应 | 12 | 68 | **P0** | 第一期 |
| 客户关系 | 10 | 179 | **P0** | 第二期 |
| 资产设备 | 6 | 84 | P1 | 第二期 |
| 质量管理 | 4 | 24 | P1 | 第二期 |

详细的 P0 表清单见 `docs/数据梳理/ERP/梳理后/01~08_字段梳理.xlsx` 各总览 Sheet。

### 1.4 同步频率建议

| 表类别 | 同步模式 | 频率 | 时段 |
|---|---|---|---|
| 主数据表（Customer, Supplier, Material, BOM） | 增量 | 每日 | 凌晨 2:00 |
| 配置表（Warehouse, Unit, Currency） | 全量 | 每周 | 周日凌晨 |
| 交易表（SalesOrder, PurchaseOrder, ProductionOrder） | 增量 | 每日 | 凌晨 3:00 |
| 流水表（InventoryTransaction, JournalEntry） | 增量 | 每日 | 凌晨 4:00 |
| 财务报表类（FI, FISTATEMENT） | 全量 | 每周 | 周日凌晨 |

### 1.5 特殊限制与风险

| 限制/风险 | 处理方式 |
|---|---|
| 1,989 张表无法逐一接入 | 聚焦 P0 103 张，后续按需扩展 |
| 字段无注释 | Raw 层保留字段名，Clean 层通过 `docs/数据梳理/ERP/梳理后/` 补充中文说明 |
| 日志/临时表混杂（`_LOG`, `_TEMPLATE`, `_BAK`） | 默认排除 `_LOG`, `_TEMPLATE`, `_BAK` 后缀表 |
| 无集中外键约束 | 关系通过 `docs/数据梳理/ERP/梳理后/ERP业务关系图谱边.xlsx` 补充 |
| 部分表无时间戳字段 | 增量用 hash 对比兜底（仅限小表） |
| 主表数据量可能百万级 | 分批 20,000-50,000 行/批 |
| Schema 版本变化风险 | 版本升级后执行 Schema 差异检测 |
| 财务敏感数据 | 只读账号 + 字段脱敏 + Agent 权限继承 |

### 1.6 同步顺序（Phase 编排）

```text
Phase 1: 主数据表（跨域依赖的公共表）
  CUSTOMER, SUPPLIER, MATERIAL, PRODUCT, BOM, EMPLOYEE, WAREHOUSE

Phase 2: 配置/基础表
  UNIT, CURRENCY, EXCHANGE, ACCOUNT, ACCPERIOD, PLANT

Phase 3: 交易表（依赖 Phase 1 主数据）
  销售: SALE_ORDER, SALE_ORDER_D, SHIPPING
  采购: PURCHASE_ORDER, PURCHASE_ORDER_D
  生产: PRODUCTION_ORDER, WORK_ORDER, DISPATCH

Phase 4: 流水/明细表
  INVENTORY_TRANSACTION, JOURNAL_ENTRY, JOURNAL_ENTRY_D,
  INV_COST_BAL, INV_SUMMARY
```

## 2. MES (LightMES) 同步配置

### 2.1 基本信息

| 项目 | 值 |
|---|---|
| 系统名称 | LightMES |
| 接口协议 | REST API（全部 POST） |
| 接口梳理文档 | `docs/数据梳理/MES/MES数据查询接口梳理.xlsx` |
| 接口总数 | 25 个 |
| QPS 限制 | **10 QPS**（客户端账号级别） |

### 2.2 策略选型

| 决策项 | 选择 | 理由 |
|---|---|---|
| **同步策略** | API 拉取同步 | 无数据库直连，仅提供 REST API |
| **分页模式** | 偏移分页（默认） | 接口支持 page/pageSize |
| **Raw 存储** | JSONB 通用表 `raw_record` | 接口响应结构可能随版本变化 |
| **增量方式** | 时间范围分页 | 接口支持 `startTime`/`endTime` |

### 2.3 接口优先级

#### P0 级（第一期接入，9 个接口）

| # | 接口名称 | 端点 | 业务价值 |
|---|---|---|---|
| 1 | 工单查询 | `/open/workorderController/filterWorkorder` | 核心生产数据 |
| 2 | 查询完工报工 | `/open/workorderController/selectComplishReport` | 完工统计 |
| 3 | 工单工序查询 | `/open/workorderController/selectWorkorderProcedure` | 工序进度 |
| 4 | 工单报工数据查询 | `/open/workorderController/selectWorkorderReportDataByTime` | 报工明细 |
| 5 | 查询投料明细 | `/open/workorderController/selectTaskUseMaterial` | 物料消耗 |
| 6 | 工序报工数据查询 | `/open/workorderController/selectProceduresReportDataByTime` | 工序级报工 |
| 7 | 设备 OEE 报表 | `/open/trilightSummary/selectOeeReport` | 设备效率 |
| 8 | 异常上报记录列表 | `/open/errorReportAPIController/selectErrorReport` | 生产异常 |
| 9 | 物料查询 | `/open/material/queryCraftHours` | 物料主数据 |

#### P1 级（第二期接入，10 个接口）

| # | 接口名称 | 端点 |
|---|---|---|
| 10 | 工单排产参数查询 | `/open/workorderController/selectProductionBackParamsByTime` |
| 11 | 工单任务明细查询 | `/open/workorderController/selectWorkorderTaskActionStatistics` |
| 12 | 安灯报表 | `/open/trilightSummary/andonApiController` |
| 13 | 获取三色灯指定时间段内消息数量 | `/open/trilightSummary/getTimecountMessagesByTimeSim` |
| 14 | 获取三色灯指定时间段内消息数量之和 | `/open/trilightSummary/getTrilightCountByTimeSim` |
| 15 | 通过 sim 编号查询对应灯状态 | `/open/trilightSummary/getTrilightCurrentColor` |
| 16 | 批量获取灯状态 | `/open/trilightSummary/getTrilightCurrentColorList` |
| 17 | 查询指定时间三色灯颜色变化信息 | `/open/trilightSummary/getTrilightSummaryDurationTime` |
| 18 | 指定日期一天灯状态 | `/open/trilightSummary/getTrilightEfficiencyOneDay` |
| 19 | 灯指定时间灯效率 | `/open/trilightSummary/getTrilightEfficiencyDurationTime` |

#### P2 级（第三期接入，6 个接口）

| # | 接口名称 | 端点 |
|---|---|---|
| 20 | 查询团队设备数量 | `/open/machine/getMachineCount` |

| 25 | 物料查询详情 | `/open/material/queryCraftHoursDetails` |

### 2.4 同步频率建议

| 接口类别 | 同步模式 | 频率 | 时段 |
|---|---|---|---|
| P0 工单/报工/投料 | 增量（时间窗口 24h） | 每日 | 凌晨 2:00 |
| P0 设备 OEE | 增量 | 每日 | 凌晨 2:30 |
| P0 异常上报 | 增量 | 每日 | 凌晨 2:30 |
| P0 物料查询 | 全量（数据量小） | 每日 | 凌晨 3:00 |
| P1 三色灯状态 | 全量（实时性要求高） | 每小时 | — |
| P2 设备/自定义字段 | 全量 | 每日 | 凌晨 3:30 |

### 2.5 特殊限制与风险

| 限制/风险 | 处理方式 |
|---|---|
| 10 QPS 限流 | 令牌桶限流，默认 8 QPS（留余量） |
| 时间范围查询限制 1 天 | 增量时按 24h 窗口分批，初期全量需按天循环拉取历史 |
| 接口全部 POST | 统一使用 POST + JSON Body |
| 部分接口无总数返回 | 以 `len(records) < pageSize` 判断最后一页 |
| 工单数据可能跨多个接口关联 | 通过 workorder_id 在 Clean/Serving 层关联 |

### 2.6 初始全量拉取策略

MES 初始全量拉取（补历史数据）：

```text
for day in range((today - 365), today):
    for each P0 endpoint:
        body['startTime'] = day.isoformat()
        body['endTime'] = (day + 1).isoformat()
        pull and write to raw_record
        sleep(0.1s between requests)  # 10 QPS 限流
```

预计首次全量（365 天 x 9 个 P0 接口）约需 1-2 小时（受 QPS 限制）。

## 3. SRM 同步配置

### 3.1 基本信息

| 项目 | 值 |
|---|---|
| 系统名称 | SRM（供应商关系管理） |
| 接口协议 | REST API |
| 接口梳理文档 | `docs/数据梳理/SRM/梳理后/` |
| 接口分类 | 8 类（基础资料、采购协同、销售协同、携选工品、系统工作台、OA 工作流、免密登录、附件上传下载） |

### 3.2 策略选型

| 决策项 | 选择 | 理由 |

| 采购协同 | 采购订单查询 | 采购交易数据 |
| 采购协同 | 送货单查询 | 物流数据 |

| 类别 | 接口 | 业务价值 |

| 采购协同 | 送货单详情查询 | 送货明细 |
| 销售协同 | 相关接口 | 销售协同数据 |

#### P2 级（第三期接入）

| 类别 | 接口 |
|---|---|
| 携选工品 | 相关接口 |
| 系统工作台 | 配置接口 |
| 免密登录 | 配置接口（仅元数据） |
| 附件上传下载 | 附件接口（大文件特殊处理） |

### 3.4 同步频率建议

| 接口类别 | 同步模式 | 频率 | 时段 |

### 3.5 特殊限制与风险

| 限制/风险 | 处理方式 |
|---|---|
| 接口文档需确认分页支持 | 梳理文档中未明确分页参数，接入前需实测确认 |
| 附件上传下载接口 | 附件不入 raw_record（数据量大），仅记录附件元数据 |
| 免密登录接口 | 仅元数据类接口，低频同步 |

## 4. 跨系统数据关联与对齐

### 4.1 关键主数据对齐

三个系统存在共享的主数据对象，需要识别和对齐：

| 业务对象 | ERP | MES | SRM | 对齐方式 |
|---|---|---|---|---|
| 物料 | ITEM / MATERIAL | 物料查询接口 | 物料信息列表 | 以 ERP 物料编码为基准，MES/SRM 通过编码映射 |
| 供应商 | SUPPLIER | — | 供应商列表 | 以 ERP 供应商编码为基准 |
| 客户 | CUSTOMER | — | — | 仅 ERP |
| 员工 | EMPLOYEE | — | 员工信息列表 | 以 ERP 员工编码为基准 |
| 工单 | PRODUCTION_ORDER | 工单（workorder） | — | ERP 工单号与 MES workorder_id 关联 |
| 采购订单 | PURCHASE_ORDER | — | 采购订单 | ERP 采购订单号与 SRM 采购订单号关联 |
| BOM | BOM | 物料查询详情（含工艺路线） | — | 以 ERP BOM 为基准 |

## 5. 首次接入执行计划

### 5.1 总体顺序

```text
第 1 步：ERP 主数据表全量同步（Phase 1: Customer, Supplier, Material, BOM...）
第 2 步：ERP 交易表全量同步（Phase 3: SalesOrder, PurchaseOrder, ProductionOrder...）
第 3 步：ERP 配置表 + 流水表同步（Phase 2 + Phase 4）
第 4 步：SRM 基础资料全量拉取（供应商、物料、员工）
第 5 步：MES P0 接口全量拉取（工单、报工、设备 OEE）
第 6 步：SRM 交易数据全量拉取（采购订单、送货单）
第 7 步：配置增量调度，进入日常 T+1 模式
```

### 5.2 预计时间

| 步骤 | 预计耗时 | 主要瓶颈 |
|---|---|---|
| ERP 主数据表（Phase 1） | ~10 分钟 | 数据量小 |
| ERP 交易表（Phase 3） | ~30-60 分钟 | 大表可能百万行 |
| ERP 流水表（Phase 4） | ~1-2 小时 | 流水表数据量最大 |
| SRM 基础资料 | ~10 分钟 | 数据量小 |
| MES P0 接口全量 | ~1-2 小时 | 10 QPS 限流 |
| SRM 交易数据 | ~20 分钟 | 取决于分页实现 |

首次总耗时预计 **3-5 小时**（可在非工作时段执行）。
